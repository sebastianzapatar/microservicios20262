01. ¿Qué es Kubernetes (K8s)?

Kubernetes es el "director de orquesta" que decide dónde y cómo se ejecutan los paquetes creados por Docker.

🌐
Open-Source
Plataforma diseñada para automatizar el despliegue, escalado y operación de aplicaciones.
🎼
Orquestador
Mientras Docker empaqueta la app, K8s gestiona el ecosistema de esos contenedores.
🏢
Estándar Industrial
Creado originalmente por Google (Borg) y ahora gestionado por la CNCF.

02. Problemas que resuelve

Antes de Kubernetes, gestionar contenedores en producción era un caos. Kubernetes automatiza la recuperación, el autoescalado y permite actualizaciones sin tiempo de inactividad (Zero Downtime).

📉
Escalabilidad manual
Soluciona la dificultad de escalar contenedores arriba/abajo rápidamente según el tráfico.
⚠️
Falta de tolerancia a fallos
Si un contenedor moría en la madrugada, alguien tenía que reiniciarlo. Ahora hay Self-Healing.
🎭
Inconsistencia
"En mi máquina funciona", elimina las diferencias entre ambientes (Dev, Staging y Prod).

03. Arquitectura y Componentes

Kubernetes se divide en dos partes principales: El Cerebro y los Trabajadores.

🧠 Control Plane (El Cerebro)

  • 🔹 API Server: El punto de entrada para todas las comunicaciones.
  • 🔹 etcd: Base de datos clave-valor que guarda el estado del clúster.
  • 🔹 Scheduler: Decide en qué nodo se ejecuta cada Pod.

👷 Worker Nodes (Los Trabajadores)

  • 🔸 Kubelet: El agente que asegura que los contenedores estén corriendo.
  • 🔸 Pod: La unidad mínima de ejecución en K8s (uno o más contenedores).
  • 🔸 Kube-Proxy: Maneja las reglas de red.

04. Conceptos Clave

Elementos principales con los que interactuarás en Kubernetes.

📜
Deployment
Define el estado deseado (ej. "quiero 3 réplicas de este Pod en todo momento").
🔗
Service
Provee una dirección IP y nombre de dominio estable, actuando como balanceador de carga interno.
🌐
Ingress
Expone rutas HTTP/HTTPS desde el exterior hacia los servicios del clúster.
🔐
ConfigMap & Secret
Inyectan configuración y contraseñas a los Pods sin reconstruir la imagen.

05. Beneficios para Empresas

🏥
Alta Disponibilidad
Reinicia automáticamente contenedores que fallan (Self-Healing).
📈
Auto Escalabilidad
Agrega más Pods si hay un pico de usuarios (HPA).
☁️
Portabilidad
Funciona en AWS, Azure, GCP o servidores locales sin cambiar código.
🔄
Zero Downtime
Permite hacer "Rolling Updates" sin que el usuario note una caída.

06. Casos de Uso Comunes

  • ✦ Arquitecturas de Microservicios: Escalar cada servicio de manera independiente (ej. el servicio de Historial Médico vs. el Gateway).
  • ✦ APIs REST de alto tráfico: Balancear millones de peticiones diarias automáticamente.
  • ✦ Pipelines CI/CD: Integración y despliegues totalmente automatizados con rollback inmediato si algo falla.
  • ✦ Sistemas Big Data y Machine Learning: Coordinación eficiente de tareas distribuidas intensivas.

07. ¿Cuándo usar K8s?

✅ Cuándo SÍ usarlo

  • 🧩
    Tienes múltiples microservicios interactuando.
  • 📈
    Necesitas escalabilidad horizontal automática.
  • ☁️
    Quieres evitar el "Vendor Lock-in" (independencia del proveedor cloud).
  • 🧑‍💻
    Cuentas con un equipo DevOps preparado.

❌ Cuándo NO usarlo

  • 🏗️
    Tienes una aplicación monolítica pequeña.
  • 📚
    Falta de experiencia previa con contenedores.
  • 💰
    El costo y complejidad no se justifican frente al tráfico.
  • 🛡️
    No requieres alta disponibilidad real (sistemas internos simples).

11. Demo: del código al clúster

Cuatro pasos para pasar de docker compose a un clúster real de Kubernetes.

1️⃣
Construir dentro de Minikube
Los manifiestos usan imagePullPolicy: Never: las imágenes deben existir en el nodo, no en Docker Hub.
minikube start --cpus=4 --memory=8192
eval $(minikube docker-env)
docker build -t eureka-server:latest ./eureka-server
2️⃣
Cargar el realm de Keycloak
Un JSON grande no cabe cómodo en un YAML: el ConfigMap se crea desde el archivo.
kubectl create configmap keycloak-realm-config \
  --from-file=realm-export.json=keycloak/realm-export.json
3️⃣
Desplegar
Un solo comando aplica los 22 objetos. Kubernetes reintenta hasta converger al estado deseado.
kubectl apply -f k8s/
kubectl get pods -w
4️⃣
Abrir los puertos
Los Pods viven dentro del clúster; port-forward es el puente hacia tu máquina.
kubectl port-forward svc/keycloak-salud 8080:8080
kubectl port-forward svc/gateway-service 8090:8090

12. Self-Healing y Escalado en vivo

La diferencia real entre un Pod suelto y un Deployment se ve en 10 segundos.

💀 Mata un Pod... y renace

# Eliminamos el Pod de pacientes kubectl delete pod -l app=pacientes-service # Kubernetes crea uno nuevo al instante kubectl get pods -l app=pacientes-service -w
  • ✦ El Deployment detecta 0 réplicas cuando debería haber 1
  • ✦ Crea un Pod nuevo, con nombre nuevo, sin intervención humana

📈 Escala horizontalmente

# De 1 a 3 réplicas kubectl scale deployment pacientes-service \ --replicas=3 # Las 3 se registran en Eureka kubectl get pods -l app=pacientes-service
  • ✦ Las 3 réplicas se registran solas en Eureka
  • ✦ El Gateway balancea entre ellas: por eso las rutas usan lb://
